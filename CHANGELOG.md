### Fixed

- Phase 12.19H sync result resilience — added a process-level last-known-good (LKG) cache to `getDashboardLiveSyncResult()` in `server-runtime.ts`. Previously every page navigation made a fresh `synchronizeWorldCup2026Results()` call with no cross-request staleness protection; when the external provider rate-limited or errored it fell back to local static data (no `kickoffAt`), making every date-scoped view show zero matches. The LKG cache stores the most recent successful (non-fallback) sync result in module memory and serves it — with a staleness warning — whenever a subsequent call returns a degraded response (`localFallbackUsed === true`). The `getDashboardLiveSyncResult` signature now accepts an optional `syncFn` parameter for deterministic testing; `resetSyncResultCache()` is exported for test isolation. Added 5 targeted unit tests covering: fresh data updates LKG, degraded response serves LKG with staleness warning, degraded response with no prior LKG is served as-is, valid response after degraded state replaces LKG, and rapid concurrent degraded requests all receive the same valid LKG result. No prediction formula, Elo/xG, Poisson, provider, persistence, snapshot, evaluation, schema, standings, qualification, or official fixture behavior changed.
- Phase 12.19H Matches Experience defect fixes — resolved four defects in the `/matches` route introduced when the external provider began returning Round-of-32 fixtures: (1) added a stable `PROVIDER_FIXTURE_ALIASES` map in `server-runtime.ts` so `/matches/537417` resolves to the canonical `wc2026-match-73-south-africa-vs-canada` ID and never returns a 404 even when the provider is temporarily offline; (2) fixed `/matches` daily date filtering so fixtures that lack a kickoff timestamp (`unscheduledMatches`) are excluded from the date-scoped list — previously all 72 group-stage local-static fixtures (no `kickoffAt`) appeared on every requested date; (3) added `getLocalDateFromKickoff` to `matches-experience.ts` to convert a UTC ISO timestamp to a Colombia-local `YYYY-MM-DD` date (America/Bogota, UTC-5), fixing the match-detail back link which was using `.slice(0, 10)` and therefore pointing to the UTC date rather than the correct Colombia date for late kickoffs; (4) renamed the back-link label from `All matches` to `Back to matches` for accuracy. Added 3 unit tests for `getLocalDateFromKickoff` (same-day UTC, UTC midnight crossing, late-night crossing) and 1 unit test for the alias-map fallback behavior. Updated the Playwright `matches.spec.ts` back-link assertion. No prediction formula, Elo/xG, Poisson, provider, persistence, snapshot, evaluation, schema, standings, qualification, or official fixture behavior changed.
