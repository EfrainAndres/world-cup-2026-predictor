# Data Sources Research

This document identifies candidate data sources for future data pipeline work. Phase 0.6 does not download datasets or create ingestion code.

## Source Selection Principles

- Prefer legally usable sources with clear licenses or public terms.
- Prefer stable files or APIs over fragile scraping.
- Preserve raw source files unchanged when ingestion begins.
- Record source URL, retrieval date, license notes, and transformation steps.
- Use official FIFA sources for World Cup 2026 tournament facts when available.
- Use one simple MVP source before combining many sources.

As of 2026-06-08, future ingestion should still verify teams, groups, fixtures, and venues directly against official FIFA pages before model or dashboard publication.

## MVP Recommended Data Source

Recommended MVP path:

1. Use the Kaggle international results CSV as the initial historical match dataset, only after confirming license and update date.
2. Compute an internal Elo baseline from that historical dataset.
3. Use official FIFA pages for World Cup 2026 teams, groups, fixtures, and venues.
4. Store source metadata with retrieval dates and notes.
5. Add data validation before using the data for model results.

This balances speed, reproducibility, and source-of-truth discipline.

## Data Freshness Considerations

Future pipeline metadata should track:

- Source name.
- Source URL.
- Retrieval date and time.
- Source version or update date when available.
- Row count.
- Date range covered.
- Known missing fields.
- License or usage note.

Freshness rules should be stricter for tournament fixtures and results than for older historical matches.

## Licensing And Usage Considerations

Before committing raw data or publishing derived outputs:

- Confirm dataset license.
- Confirm whether redistribution is allowed.
- Avoid scraping sites that prohibit automated extraction.
- Prefer storing ingestion scripts and metadata over committing large raw files.
- Cite source URLs in generated reports.
- Keep manual corrections documented.

## Future Data Source Improvements

Later phases may add:

- Official or licensed sports APIs.
- Player/squad availability data.
- Expected goals data if licensing permits.
- Travel distance and venue metadata.
- Rest days and fixture congestion.
- Weather or altitude context.
- Market odds only as a benchmark, if ethically and legally appropriate.
